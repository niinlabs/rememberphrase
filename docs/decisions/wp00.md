# WP00 — Safety and word-list decisions

**Status: Approved 2026-10-24.** These decisions define what Rememberphrase may build and claim. Changing one needs a new approved decision.

**Amended 2026-10-24:** D7 row 3 now requires a silent local check instead of a visible disposable sample, as part of the revised Prepare step. The green wording was also revised so the Airplane-mode limit reads as information, not an error.

**Amended 2026-10-25:** D5 now keeps step-3 edits when the count is raised; only lowering it warns first.

## D1 — Offline boundary

Version 1 works offline only in the tab that is already open. There is no offline reopening, service worker or downloadable copy. The interface tells users: "Keep this tab open. If you close or reload it, you will need to go online and start again."

**Why:** it is the only model consistent with storing nothing in the browser.

## D2 — Languages

Version 1 is English only, for both the interface and the word list. Other languages ship only once a reviewed word list and reviewed copy exist for them.

## D4 — Word count

Range 4–12, default 6. Guidance depends on the number of intact random words (D8):

| Intact random words | Guidance |
|---|---|
| 0–3 | "Too few random words for an important password." |
| 4–5 | "Shorter than we recommend for a master password or computer login." |
| 6 or more | "The length we recommend for a master password or computer login." |

**Why:** six matches EFF's recommendation; four words give roughly 2⁵² combinations against 2⁷⁷ for six. The guidance never says "secure".

## D5 — Changing the count with locked words

Raising the count adds new random words at the end, and after step-3 edits adds them to the end of the arranged phrase, keeping the edits. Lowering it removes unlocked words from the end; if that would remove a locked word, it stops and says "Unlock N words to go down to X words." Lowering the count after step-3 edits warns first.

## D6 — The "Confirming offline" check

- A request to `/reachability.txt` with a fresh query string, `cache: 'no-store'`, no credentials, no referrer and `redirect: 'manual'`, so redirects are never followed. It runs once after the user confirms Airplane mode, before any real phrase exists, and never during generation.
- **Any HTTP response is positive evidence of a connection and holds generation**, including a redirect, an error status or a Wi-Fi login page. The answer is decided when the response headers arrive.
- Only a network error or the **5-second timeout** is inconclusive, and never proof of being offline.
- **Skip** cancels a pending request and is recorded as skipped. A response that arrived before Skip still counts.
- The expected marker only selects the wording: "Rememberphrase answered, so you are still connected" or "A network answered (this can be a Wi-Fi login page). You may still be connected."

**Why:** any reply proves a working network path; a rare false warning is the safer mistake.

## D7 — Connection status table

Checked when the check finishes, on every Generate and Reroll, and on browser `online`/`offline` events. The first matching row wins. Implemented in `src/core/status.ts`.

| # | Condition | State | Real generation |
|---|---|---|---|
| 1 | Word list not ready, or secure random numbers unavailable | Amber | Held |
| 2 | The check got any response, or the browser reported coming online after the user confirmed offline | Red | Held until the user confirms again and the check runs again |
| 3 | Offline not confirmed, check not finished, or no successful local check | Amber | Held |
| 4 | Check skipped, or the browser still reports `navigator.onLine === true` | Amber, naming the reason | Allowed |
| 5 | Check failed or timed out, and the browser reports offline | Green: "You confirmed offline, and the word list is ready in this tab." with the note "Good to know: websites can't see your device's Airplane mode setting, so this relies on your own check." | Allowed |

**Row 4:** `navigator.onLine` often stays `true` in Airplane mode when a VPN or virtual network adapter exists. The copy says so: "Your browser still reports a network connection. This can be a VPN or virtual adapter; check Airplane mode."  
**Row 3, local check:** once the user has confirmed offline and the check has ended without a response (including Skip), the tab silently draws a few words from the loaded list and discards them unseen. It is never displayed, logged, stored or sent, and makes no requests. Success shows the tab can make words; it is not evidence about the network. If it fails, preparation holds and the user can retry the check or confirm again. If the browser has no random source at all, confirming is disabled and the page explains why.  
**Row 2, red interruption:** any response, or a reconnection after confirmation, opens a red alert with an Acknowledge button. Acknowledging closes the alert only: the red hold stays, the confirmation is cleared, and the user must confirm again and run a new check.  
**Row 2 mid-session:** a phrase already on screen stays visible, and the site never claims it was transmitted.

## D8 — Strength explanation

- Count intact random words: generated words whose text is unchanged. An intact combined token counts as two. Any edit removes intact status; a fully rewritten word is user-written even if it is in the list.
- Show the D4 guidance, the intact random-word count, the list size and the character count, with the caveat: "Based on how these words were generated. You chose which words to keep and their order; we do not count that as extra strength."
- Connecting words, separators, substitutions, capitals, digits and symbols never change the guidance level.
- No bit counts, combination counts or crack times for the user's own phrase. No pattern-based estimator in version 1. If every word was rewritten: "We cannot estimate the strength of words you wrote yourself."

## D9 — Destination rules and decoration

- Default: "Requirements not specified."
- The user can state minimum and maximum length; required uppercase, lowercase, digit or symbol; spaces not allowed; and use at a start-up screen or on another keyboard layout (which warns about non-ASCII characters).
- Controls: Capitalise (first word or every word), Add a number, Add a symbol. Other substitutions are suggested as tips and made by editing a word.
- The checklist reports only rules the user stated and never claims a service will accept the phrase.

## D10 — Separators and edit limits

- Separators: space (default), hyphen, period or underscore; one choice for the whole phrase. A combined token has no separator inside it.
- Each word: 1–32 characters; no line breaks, tabs or control characters; no leading or trailing spaces; normalised to Unicode NFC. Non-ASCII characters are allowed but trigger the keyboard warning.

## D11 — Connecting words (English)

`the`, `a`, `and`, `in`, `on`, `with`, `for`, `of`, `to`, `at`, `under`, `near`. Each can be inserted any number of times, moved and removed. They are always shown differently from random words and never counted as random.

## D12 — Combining, splitting, reset and duplicates

- Combine joins two adjacent single generated words, never connecting words or an existing combination. Both keep their draw identity and lock.
- Split is available only while the combined text is unchanged; after an edit, "Reset my changes" restores the generated set.
- Reset restores the latest generated set without new random draws; Back keeps the draft; Start fresh warns and draws a new set under the offline check.
- Duplicate words are allowed, with the note "This word appears twice. You can reroll it if you like." There is no strength adjustment.

## D13 — Practice and recovery

- Version 1 never asks the user to type the phrase back into the site. Practice is a story exercise, recalling the words before revealing them, and practising at the real login.
- Recovery: write the phrase on paper and keep it away from the device; never a photo, cloud note, chat message or file. For a password manager, also point to its own recovery or emergency-kit feature.
- A "Clear phrase" button clears the phrase from the page. The site does not promise that every trace is erased.

## D14 — Threat model

- **In scope:** the phrase leaving the tab over the network; the site storing anything; misleading strength or safety claims; an attacker who knows the method and word list guessing the phrase.
- **Reduced, not eliminated:** tampered page delivery (strict Content Security Policy, first-party assets, pinned dependencies, public source); a connected device during generation (offline guidance and the D6 check).
- **Out of scope, stated in the interface:** a compromised device, malicious browser extensions, someone watching the screen, and what the browser or operating system keeps on its own.

## D15 — Tooling

Svelte 5, TypeScript, Vite, Vitest and Playwright. Each work package has a verifier, `scripts/verify-wpNN.mjs`, that prints PASS, FAIL or BLOCKED and exits non-zero unless everything passes. Attribution lives in `ATTRIBUTION.md` and in the interface.

## D16 — Deferred

Offline reopening or a downloadable copy; a second language; brand and trademark clearance (before public launch); a pattern-based strength estimator; Trusted Types enforcement; hosting provider.
